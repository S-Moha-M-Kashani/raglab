raglab · a retrieval workbench

Choices by measurement,
never by taste.

Every RAG tutorial hands you a chunk size, a retriever, an embedder — and no evidence. RAG lab is a workbench where each of those choices is a knob, and a scored experiment is what turns one.

Moha Kashani · github.com/S-Moha-M-Kashani/raglab

01 · why measure

One knob moved. Nothing else.

0.617 → 0.01

Recall on the same corpus, same retriever, same prompts — swapping a real bilingual encoder for a hash baseline that embeds Farsi to the zero vector.

A demo would have looked fine. The measurement did not. That gap is the reason this project exists.

02 · the pipeline

Three steps, every stage a knob.

Indexing

  • six chunkers
  • five embedders
  • optional summary hierarchy — Leiden, Louvain, RAPTOR, …
  • in-memory store, no vector database
what gets stored

Retrieval

  • query understanding
  • dense · BM25 · hybrid fusion
  • six rerankers, three graders
  • a Farsi text normaliser
what gets found

Generation

  • extractive or LLM answerer
  • answerer and judge are never the same model
  • every degraded answer carries its reason
what gets written

03 · rules of evidence

Exactly four metrics vote.

  • faithfulness
  • answer relevancy
  • context precision
  • context recall

One knob per candidate

A sweep moves a single setting and holds every model fixed, so a score difference has one possible cause.

The judge is screened

A model must pass a screening gate before it may grade — and it can never be the model that answered.

Grouped before ranked

Runs compare only inside one (dataset, question set, judge) group. Across groups there is no ranking at all.

No winner inside the error

The decision score never appears without its spread, and a verdict refuses when the lead sits inside the combined error.

04 · honesty rules

A row must never lie about what produced it.

Refusal over substitution

A model the backend does not serve is a refusal, never a silent swap — embedders, chat models, and hierarchy partitions alike.

Unparsable costs work

A verdict that cannot be parsed is read in the direction that costs more work, never as a passing default.

Rebuilds are a promise

An index config fingerprints to a collection name; the same fingerprint means the same build, months later.

The suite stays offline

1219 tests run on a fake backend with temporary databases — no key, no network, no live model.

05 · the surfaces

One origin, one port, four pages.

surfaceroutewhat it does
Panel/the knob surface — configure, build, run, score
Inspector/inspectorread-only: chunks, traces, verdicts, evidence
Leaderboard/leaderboardone sortable table per dataset — it names no winner
Ask widgeteverywherean agentic helper with 10 tools and two kinds of memory — it advises, you decide

The helper writes no run, no ledger row, no score — it sits outside the measured seam, which is exactly what allows it to trace to LangSmith.

06 · the data

Seven corpora with known answers.

A synthetic one-year diary in English and Farsi (167 sessions each), German meeting notes, an English support desk, a multi-hop research set, and a smoke corpus — because a finding that only holds on one corpus is a preference wearing a number.

Any corpus/ground-truth pair that passes the machine-checked import contract can be measured the same way. Bilingual retrieval is where taste fails loudest — see slide 01.

07 · close

If you didn't measure it, it's a preference — not an architecture.
